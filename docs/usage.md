# Gasho の使い方

Gasho の画面でできることを、場所ごとにまとめる。入れ方は [hub-setup.md](hub-setup.md) と [daemon-setup.md](daemon-setup.md)、working server のコマンドは [cli.md](cli.md) を見る。

古い gasho-daemon の working server では、ここに書いた機能の一部が出ない。その機能を使うには、「端末」の画面から gasho-daemon を更新する。

## セッションを起動する

ホームの「新しいセッション」を押して、working server とフォルダーを選ぶと、そのマシンで `claude --remote-control=<名前>` が起動する。サイドバーにある worktree で起動するなら、セッション画面のタブの右の「＋」で、すぐ起動できる。起動したセッションには、Gasho の入力欄から指示を送れる。公式アプリ（スマホ・Desktop）からも、同じセッションを操作できる。

- フォルダーの一覧に出るのは、Claude Code が信頼しているフォルダーと、その親フォルダー（`~/repos` など）。一覧にないフォルダーは「ほかのフォルダーを入力する…」で絶対パスを入れる
- 名前を付けずに起動したセッションは、はじめ「<フォルダー名>-gasho」で、最初の発言のあと、Claude Code がその発言から付けたタイトルに変わる。その前に名前を変えたときは、変えた名前のまま
- 起動したセッションの記録は working server の `~/.config/gasho/managed.json` に残り、gasho-daemon を起動し直しても引き継ぐ

### フォルダーを作る・clone する

新しいセッションのフォームでは、選んだフォルダーの中に新しいフォルダーを作ったり、GitHub のリポジトリを clone したりできる。1つのフォルダーに複数のリポジトリを置き、そのフォルダーでセッションを起動する使い方にも使える。

- 「新しいフォルダー」：名前を入れて「作る」を押すと、選んだフォルダーの中にフォルダーができ、そのフォルダーが選ばれる。続けて clone すると、その中に入る
- 「GitHub から clone」：`owner/name` か GitHub の URL を入れて「clone する」を押すと、working server で `gh repo clone` が動く。フォルダーの名前は、空ならリポジトリの名前になる。clone したあとも選んだフォルダーはそのままなので、同じフォルダーに続けて clone できる。clone したリポジトリで起動するときは、「このフォルダーを選ぶ」を押してから起動する
- clone には working server の GitHub CLI（`gh`）とそのログインを使う。gh と git は端末なしで動かすので、パスワードや SSH のホスト鍵を尋ねられる場合は失敗する。10分で終わらない clone は止める
- 同じ名前のフォルダーやファイルがあるときは、作らず、clone もしない。名前に `/` は使えない（1階層ずつ作る）。`-` で始まる名前、`.`、`..` も使えない
- 作ったフォルダーと clone したリポジトリは、フォームを開いているあいだ、フォルダーの一覧に出る。そこで起動して Claude Code が信頼すると、それからは一覧にいつも出る

### まだ信頼していないフォルダー

clone したリポジトリは、親のフォルダーを信頼していても、Claude Code はまだ信頼していない（リポジトリの外のフォルダーの信頼を、リポジトリの中に引き継がない）。こうしたフォルダーで起動すると、Claude Code が信頼するかを尋ね、起動はそこで止まる。フォームには、そのことと、Claude Code からの注意（フォルダーの設定が前もって許可しているコマンドなど。英語のまま）が出る。

- 「信頼して起動する」を押したときだけ、gasho-daemon が Claude Code の確認で「Yes, I trust this folder」を選ぶ。カーソルが Yes にあることを画面で確かめてから、Enter を1回だけ押す。信頼したことは Claude Code に保存され、次からは尋ねられない
- 信頼すると、Claude Code はそのフォルダーのファイルを読み書きし、コマンドを実行できるようになる。フォルダーの中の設定（`.claude/settings.json` の許可や hooks など）も使う。自分で作ったものや、よく知っているリポジトリだけを信頼する
- 信頼のあとで、フォルダーの `.mcp.json` にある MCP サーバーを使うかを Claude Code が尋ねたときは、Esc で答えて、使わずに起動する。Claude Code はこの答えをフォルダーの `.claude/settings.local.json` に保存する。起動したあとで、そのことを知らせる。使うときは、端末で `claude` を起動し、`/mcp` から有効にする
- 信頼しているフォルダーの中に作ったフォルダー（リポジトリでないもの）は、その信頼を引き継ぐので、確認は出ない

### セッションの端末

セッションは、gasho-daemon がセッションごとに用意する端末（`gasho-<名前>-xxxx`）の中で動く。端末は gasho-daemon とは別のプロセスで、Ubuntu では systemd のスコープの中で動くので、gasho-daemon を動かし直してもセッションは止まらない。SSH から `gasho-daemon attach <その名前>` で直接見て、そのまま操作することもできる（Ctrl+] で抜ける。名前を付けずに実行すると、端末の一覧を出す）。

`/exit` を送るか公式アプリで終了すると、gasho-daemon がセッションの端末も閉じる。

### Gasho の外で起動したセッション

セッションの一覧に出すのは、Gasho が起動したセッションだけ。端末や `claude rc` で起動したセッションは、一覧にも通知にも出さない。`claude rc` が起動したセッションには、外から入力する公式の手段がないので、公式アプリから操作する。

Gasho の外（Orca や端末）で起動した Claude Code が、サイドバーにある worktree で会話を開いていると、タブの上に「Gasho の外で N 件の会話が開いています」と出す。「Gasho に移す」を押すと、その会話の一覧を確かめるダイアログを出し、「終了する」で、それらの Claude Code に SIGTERM を送って終了させる。元の端末は閉じない。会話の記録は残るので、終了した会話は過去の会話に出て、続けたいものだけを Gasho で開き直せる。8秒待っても終わらない Claude Code は止めずに残し、元の端末で終了するよう伝える。バックグラウンドで動いている会話（`claude agents` に PID が無いもの）は、終了できないので数えない。

## サイドバーの worktree

サイドバーには、セッションがある worktree を、working server に分けずに1つの一覧で出す。どの worktree のセッションかは、gasho-daemon がセッションの作業フォルダーで git を流して調べる。

- 各行にはブランチ名（ブランチが無いときはフォルダー名。名前を付けた worktree はその名前）とリポジトリ名を出し、working server が2台以上あるときはその名前も出す
- 最後に会話があったセッションの worktree から並べ、まだ会話がないセッションは起動した時刻で数える
- 確認を待っているセッションがある worktree には「確認」、オフラインの working server の worktree には「オフライン」と出す
- リポジトリの外のフォルダーのセッションは、作業フォルダーごとに1行にする
- セッションがすべて無くなった worktree も、ブラウザーが覚えていて、一覧の最後に残す。その worktree を押すとセッションの無い worktree の画面が開き、「サイドバーから外す」で一覧から外せる。覚えるのはそのブラウザーだけなので、スマホと PC では別になる

### リポジトリを登録する

リポジトリを登録すると、その worktree を、Gasho のセッションが無くても一覧に出す。登録したリポジトリの worktree は、ブラウザーが覚えるのではなく、git の一覧に合わせて出し入れする。

- 一覧の見出しの右にある絞り込みのボタンから「リポジトリを登録・解除…」を開き、working server ごとにリポジトリを選ぶ
- 候補は、Claude Code が信頼しているフォルダーとセッションのフォルダーのリポジトリ。worktree のフォルダーや、本体と worktree を並べた親フォルダーは、その本体の1行にまとめる（Git でないフォルダーは出さない）。gasho-daemon が5分おきに git で調べ、行には本体のフォルダー名・パス・worktree の数を出す。検索欄で名前やパスを絞り込み、行を押すと登録する
- 一覧に無いフォルダーは、パスを入れて登録する。worktree のフォルダーを入れると、そのリポジトリの本体のフォルダーを登録する。リポジトリの外のフォルダーを入れると、その直下にある worktree が1つのリポジトリのものなら、そのリポジトリを登録する（本体と worktree を1つの親フォルダーに並べる置き方）。直下に別々のリポジトリがあるときは登録しない
- gasho-daemon が `git worktree list` を 10 秒おきに読み、セッションのある worktree の後ろに並べる。Orca や git で worktree を足したり消したりすると、一覧も変わる
- 登録は gasho-daemon の置き場（`~/.config/gasho/repos.json`）に残るので、どのブラウザーにも同じ一覧が出る。登録と解除は、working server がつながっているときだけできる

### 絞り込み

絞り込みのボタンのメニューでリポジトリにチェックを付けると、そのリポジトリの worktree だけを出し、見出しを「worktree · <リポジトリ名>」（2つ以上なら「、」でつなぐ）にする。チェックは複数付けられ、付けてもメニューは閉じない。「すべて」で元に戻す（1つも付けていないときも、すべてを出す）。選べるのは、一覧にある worktree のリポジトリ（登録していなくても、セッションがあれば出る）。選んだリポジトリはブラウザーごとに覚える。

### 並べ替えと幅

- worktree はドラッグで並べ替えられる。PC ではマウスで項目をそのままドラッグする（押して離すだけなら、worktree を開く）。スマホでは項目の右端のつまみをドラッグする（項目に触れて動かすと一覧がスクロールする）。キーボードでは、項目にフォーカスして Alt+↑・Alt+↓ で動かせる
- 並べ替えると、それからは最後に使った順ではなく、その並びのまま変わらない。並べ替えたあとに初めてセッションを起動した worktree は、一覧の先頭に出る。見出しの右に出る「最後に使った順に戻す」で、元の並び方に戻る。並び順はブラウザーごとに覚える
- PC では、サイドバーの右の端をドラッグして、幅を200〜360px（標準は248px）のあいだで変えられる。セッションの右に開くパネル（ブランチグラフ、ファイル、プラグインのパネル）も、左の端をドラッグして、幅を380〜620px（標準はウィンドウの幅の40%）のあいだで変えられる。ウィンドウが狭いときは、パネルを開いても会話の欄に140px残るところで止まる。端をダブルクリックすると標準の幅に戻る。端にフォーカスして ←・→ でも変えられる。幅はブラウザーごとに覚える

### worktree の名前

行には、ブランチ名の代わりに、自分で付けた名前（`#254 accordion` など）を出せる。行を右クリックして（スマホでは長押し）「名前を変更…」で名前を入れる。「名前を消す」か、空にして「変更する」を押すと、ブランチ名に戻る。名前を付けた行は、ポインターを乗せるか、キーボードでフォーカスすると、横にブランチ名（リポジトリの外のフォルダーではフォルダー名）が出る。メニューの見出しと worktree の画面にも、名前とブランチ名を出す。

名前は Gasho サーバーに保存するので、どのブラウザーにも同じ名前が出る。working server がオフラインのあいだも付けられる。Gasho の画面やコマンドで worktree を削除すると、その名前も消す。`gasho-daemon worktree name`（[cli.md](cli.md)）でも付けられる。

### worktree の削除

使い終わった worktree は、行を右クリックして（スマホでは長押し）「削除…」で、中のセッションとまとめて消せる。確認のダイアログには、フォルダー・ブランチ・working server と、一緒に終わるセッションが出る。「ローカルのブランチ <ブランチ> も消す」は既定でチェックが付いている。未コミットの変更や push していない commit があるときは、件数を出して止まり、「変更を捨てて削除」をもう一度押したときだけ消す。リポジトリの main の worktree は消せない。

### worktree をまとめて扱う

worktree の行を 1 つ押したあと、Shift キーを押しながら別の行を押すと、その間の行（画面に並んでいる順。分け方のカテゴリをまたいでもよい）をすべて選ぶ。Esc を押すか、Shift キーなしで行を押すと、選択が外れる。選んだ行を右クリックすると、選んだ worktree をまとめて扱うメニューが開く。

- 「削除…」は、選んだ worktree を、中のセッションごと 1 つずつ削除する。削除できない worktree（リポジトリの main の worktree など）は、理由を添えて対象から外す。未コミットの変更や push していない commit がある worktree は、件数を出して残し、「変更を捨てて削除」をもう一度押したときだけ消す
- 「名前を変更…」は、選んだ worktree の名前（名前が無ければブランチ名）の中の「検索文字列」を、すべて「置換文字列」に置き換える（Finder でまとめて名前を変えるときの「テキストを置き換える」と同じ）。検索文字列は文字どおりに探し、大文字と小文字を区別する。ダイアログに変更前と変更後が並ぶので、確かめてから変更する。置き換えて空になった worktree は、名前を消す。たとえば検索文字列を `feat/`、置換文字列を空にすると、`feat/264-sidebar-sticky-menu` が `264-sidebar-sticky-menu` になる
- 行を別のカテゴリへ動かせる分け方（[plugins.md](plugins.md) の P18、API 1.9）では、選んだ行の 1 つを別のカテゴリへドラッグすると、選んだ worktree がまとめてそこへ移る

選択に入っていない行を右クリックしたときとドラッグしたときは、その行だけを扱う。

### プラグインで一覧を変える

- セッションそのものを並べる一覧に置き換えられる（[plugins.md](plugins.md) の P17）。たとえば GashoPlugins の Session List Rewind は、リポジトリごとのカテゴリ（見出し）の下にセッションを並べ、セッション画面の上のタブからセッションを外す。カテゴリは見出しを押すと畳め、カテゴリもセッションもドラッグで並べ替えられる
- 行はそのままにカテゴリに分けても出せる（[plugins.md](plugins.md) の P18）。たとえば GashoPlugins の Better WorktreeList は、リポジトリごとか、確認待ち・作業中・待機中などの状態ごとのカテゴリの下に worktree を並べる。分け方は、絞り込みのボタンのメニューで選ぶ。分け方が `useOnMove` を持っていれば、行を別のカテゴリへドラッグして入れられる。入れた先は、プラグインが `useSharedState` で Gasho サーバーに保存すれば、すべてのブラウザーで同じになる

## セッション画面

worktree を押すと、その worktree で最後に開いたセッションを開く（ページを読み込み直したあとは、最後に会話があったセッション）。

### タブと過去の会話

- 画面の上には、同じ worktree のセッションを起動した順にタブで並べ、タブを押すとセッションを切り替える。作業中やバックグラウンドで何かが動いているセッションのタブには、回る印が出る
- タブの右の「＋」を押すと、その worktree の最上位のフォルダー（リポジトリの外ならセッションの作業フォルダー）で、新しいセッションをすぐ起動して開く
- タブの左の時計のボタンを押すと、その worktree の過去の会話を、新しいものから 30 件まで出す。Claude Code が worktree のフォルダー（とその中のフォルダー）に残した会話のうち、いま開いている Claude Code が無いものである。会話を押すと、その会話のフォルダーで `claude --remote-control=<名前> --resume <ID>` を起動し、Gasho が起動したセッションとして開く。名前は、会話に付けた名前か、Claude Code が付けた題になる

### 名前の変更、フォーク、削除

タブを右クリックすると（スマホでは長押し）、名前の変更、フォーク、削除のメニューが開く。working server がつながっているときだけ使える。

名前を変えると、Gasho での名前はすぐ変わる。

- gasho-daemon が Claude Code に `/rename <名前>` を送り、Claude Code での名前も変える。Claude Code は Remote Control のセッション名も変えるので、公式アプリの表示も変わる想定（公式アプリの画面ではまだ確かめていない）
- 作業中は、指示と同じように gasho-daemon が預かり、作業が終わってから送る。端末の入力欄に打ちかけの文字があるときは、それを消さずに、空くまで `/rename` を待たせる
- 端末で `/rename` したときも、Gasho の名前をそれに合わせる
- 名前は1行で、60文字まで

フォークすると、会話をそこまで引き継いだ新しいセッションが、同じフォルダーで起動する（`claude --remote-control=<名前> --resume <ID> --fork-session`）。元のセッションは、そのまま使える。

- 名前は、はじめ「<元の名前> のフォーク」になっていて、変えられる
- Claude Code は、フォークした会話を、発言やコマンドが記録されるまでファイルに書き出さない。gasho-daemon は、起動した直後に `/rename` を送って名前を付け、引き継いだ会話をすぐ Gasho に出す
- 前の発言から時間がたっていて会話も長いと、Claude Code が要約から始めるかを尋ねることがある。gasho-daemon は Esc で答え、会話をそのまま引き継ぐ。次の返答では会話をすべて読み直すので、時間とトークンが多くかかる
- ホームのトークンの数には、引き継いだ会話の分を入れない
- まだ会話がないセッションは、フォークできない

削除は、タブの右の × からも始められる（メニューの「削除…」と同じ確認が出る）。削除すると、gasho-daemon が Claude Code を終了し、セッションの端末を閉じて、Gasho の一覧から外す。開いていたセッションを削除したときは、隣のタブ（右、無ければ左）を開き、タブが無くなったら worktree の画面を開く。会話の記録は working server に残るので、過去の会話から開き直せる。

- 作業中なら、途中で止まる。待たせていた指示は送らず、添付ファイルは消える
- gasho-daemon は Claude Code に SIGTERM を送り、8秒たっても終わらなければ端末ごと止める

### ヘッダー

- タブの一覧の右端のボタンで隠せる（スマホでは画面上部のバーの右端）。ボタンはタブと一緒にスクロールせず、押しても位置が変わらない。隠すと、タブの一覧のすぐ下から会話が始まる（セッション名と状態はタブに出ている）。スマホでは、セッション名と状態をいつも画面上部のバーに出す。PC では、隠したかどうかをブラウザーごとに覚える。スマホと、高さが 500px に満たない窓（スマホを横にしたとき）では、覚えずに、セッション画面を開くたびに隠した状態から始まる
- 作業フォルダーがリポジトリでなく、その中に複数のリポジトリがあるとき（2階層下まで探す）は、「複数のリポジトリ…」と「ブランチ…」を出す。「複数のリポジトリ…」を押すと、GitHub で開くリポジトリを選べる。「ブランチ…」を押すとブランチグラフを開き、タブでリポジトリを切り替えられる

### 会話の表示

- Claude の返答は Markdown として表示する。HTML は表示せず、画像は読み込まずにリンクとして出す
- 会話は新しいほうから読み込む。上へスクロールすると、前の会話を自動で読み込んで上に足すので、そのまま遡れる。見えている発言の位置は動かない。スマホでは、スクロールが止まってから足す。読み込めなかったときは、一覧の上の「もう一度」で読み込み直す
- ツールの呼び出し（コマンドの実行など）は、その結果と一緒に1つの折りたたみにまとめる。呼び出しが続くところは、ツールの種類にかかわらず全部を1つの折りたたみにまとめる。閉じたままでも、呼び出した回数、最後に呼び出したツールとその内容、エラーになった回数がわかる。開くと、呼び出しごとの折りたたみが並ぶ
- Claude Code が会話を要約したところ（Conversation compacted）には、「会話を要約しました」の区切り線を出す。要約の本文は線の下に折りたたんでおき、押すと開く。要約は Claude Code がユーザーの発言として記録するが、Gasho では発言として出さない
- 会話の文字の大きさは、サイドバーの「設定」で 12〜20px（標準は14px）のあいだで変えられる。時刻、ツールの折りたたみ、コード、表の文字も同じ割合で変わる。入力欄とヘッダーの文字は変わらない。ブラウザーごとに覚える

### Claude が送った画像と動画

- Claude が SendUserFile（利用者にファイルを送る Claude Code のツール）で送った画像と動画は、会話の中にそのまま出す。1枚なら大きく、何枚かならタイルに並べ、説明（caption）を下に添える
- 画像を押すと画面いっぱいに開き、もう一度押すと原寸になる。同じときに送ったほかの画像と動画へは ←・→ か左右のボタンで移り、Esc で閉じる。右上のボタンで保存できる。動画はその場で再生でき、好きなところへ飛ばせる
- 画像と動画は、表示するときに working server から Gasho サーバーを通して読む。会話の記録には、ファイルのパスしか残らないためである。送ったあとで消えたファイルは「表示できません」と出し、書き換えたファイルは新しい中身で出る。gasho-daemon が読むのは、そのセッションの会話で Claude が送った画像（PNG、JPEG、GIF、WebP、AVIF、BMP、SVG）と動画（MP4、MOV、WebM、OGV）だけ
- ほかのファイル（Markdown や HTML など）は、名前だけを出す。Claude がファイルとして渡すように送ったもの（`display: "attach"`）は、画像と動画も名前だけを出し、押すと開く

### Footer

セッション画面の最下部に、1 行の Footer を出す。ホーム・端末・プラグイン・設定と、worktree のタブのプラグインの画面には出さない。

```
● 接続中 · Windows │ ubuntu メモリ ▰▱ 62% 9.9/16.0 GB   …   │ ◔ コンテキスト 36% 72.4k/200k │ 5時間 18% 2:00 後 │ 週 41% 11/29 まで │ Fable 週 12% 11/29 まで
```

- 左：Gasho サーバーとの接続と、このブラウザーの登録名。前はサイドバーの下に出していた。接続が切れると赤い点と「再接続中…」になる（スマホでは、画面上部のバーにも「再接続中…」が出る）
- 左：このセッションの working server のメモリ。ホームの「メモリ」のタイルと同じ値で、80% 以上は黄、90% 以上は赤で出す。オフラインのときは「オフライン」、メモリの値を送らない古い gasho-daemon では「未対応」と出る
- 右：そのセッションの Context Window の使用率とトークン数。Gasho から起動したセッションで、最初の返答のあとに出る
- 右：Claude.ai のプランの使用量の上限。5時間の上限（プランにあるときだけ）、週の上限（すべてのモデル）、Fable などモデルごとの週の上限を、使用率と、リセットまでの時間か日付で出す。70% 以上は黄、90% 以上は赤で出す。API キーで使っているとき、最初の返答の前、上限を読めないときは出さない
- プラグインは、メモリの右か、コンテキストの左に部品を足せる（[plugins.md](plugins.md) の P21）
- コンテキストか上限を押すと、詳細（Context Window の使用量、Sonnet の週の上限も含めた上限ごとの使用率とリセットの時刻、いつの値か）を出す。もう一度押すか、Esc か、外を押すと閉じる
- 幅が狭いときは、リセットの時刻、メモリの量、トークン数を先に省き、それでも入らないものは右の端から省く

上限は、2 つのところから取り、新しいほうを出す。

- Claude Code がステータスラインに渡す上限（5時間と週）。その working server のセッションのうち、最後に返答したものの値
- gasho-daemon が、Claude Code の `get_usage` で読んだ上限。モデルごとの週の上限は、こちらにしかない。Footer が画面に出ているあいだ、5 分より古ければ読み直し、詳細を開いているあいだは 1 分より古ければ読み直す。誰も見ていなければ読まない。gasho-daemon は、Claude Code をプロンプトなしで起動して答えを読むので、モデルは呼ばず、トークンも使わない（負荷の高い Mac では 1 分ほどかかる）。読めなかったときは、詳細に理由と「読み直す」を出す。`get_usage` に対応していない古い gasho-daemon では、ステータスラインの上限だけを出す

スマホでは、Footer を入力欄のすぐ下に置き、数字だけの短い形（● MEM 62% │ ◔ 36% │ 5h 18% │ 週 41% │ Fable 12%）にする。どれを押しても、接続とメモリも含めた詳細を出す。幅に入らないものは右から省く。ホーム画面に追加した Gasho では、iPhone のホームインジケーターのぶんの余白を Footer が受け持つ。入力欄の下の文字数（「0/20000」）の行は出さず、文字数は上限に近づいたときだけ入力欄の中に出す。

### 権限の確認

Claude Code が権限の確認を出しているあいだは、入力欄の上に確認のカードを出し、「許可」「今後も許可」「拒否」で答えられる。端末や公式アプリでも答えられ、そちらで答えるとカードは消える。「今後も許可」は、Claude Code が許可のルール（`Bash(npm test:*)` など）を提案したときだけ出る。拒否すると、端末で「No」を選んだときと同じく、Claude は作業を止めて次の指示を待つ。使うには working server に hooks を入れておく（[daemon-setup.md](daemon-setup.md) の「通知を使う」）。

## 入力欄

### 送る・止める

- 送った指示は、すぐに会話の末尾に「送信中…」と出す。Claude Code が指示を会話に記録するのは、gasho-daemon が指示を入力したときで、モデルを先に切り替えるときなどは数秒かかる。記録されると、その記録に置き換わる
- 送った時点で作業中になっていた指示（公式アプリからの発言と重なったときなど）は gasho-daemon が預かり、作業が終わってから順に送る。預かった指示は「送信待ち」と出す
- 作業中は、送信ボタンが停止ボタンに変わる。押すと Esc を送って作業を止める。続けて何度押しても、Esc は3秒に1回しか送らない（Claude Code は、Esc が続けて届くと巻き戻しの画面を開き、セッションがそこで止まるため）
- 応答が始まる前に止めると、Claude Code は止めた指示を端末の入力欄に戻す。gasho-daemon は、次の指示を貼り付ける前に入力欄を空にする
- `/clear` を送ると、Claude Code は同じ端末のまま、新しい ID で新しい会話を始める。Gasho は同じ名前のセッションとして扱い続け、開いている画面も新しい会話に移る。預かっている指示と添付したファイルも引き継ぐ

### バックグラウンドで動いているもの

- Claude がバックグラウンドで動かしているもの（`run_in_background` で動かしたコマンド、Monitor、サブエージェント、ワークフロー）は、入力欄の上の「バックグラウンドで実行中」に、説明、種類、始まってからの時間、コマンドとともに並ぶ。動いているものがないときは出ない。入力欄の Effort の右のボタン（回る印と件数）で、一覧を隠したり出したりできる（このブラウザーで覚える）。Claude の作業が終わっても動き続けるので、停止ボタン（Esc）では止まらない
- それぞれの「止める」と「すべて止める」で止められる。gasho-daemon が端末で Claude Code のタスクの一覧（`/tasks`）を開き、そのタスクで x を押して閉じる。端末で手で止めたときと同じく、Claude には止めたことが伝わる。端末の入力欄に書きかけの文があるときと、権限の確認などが開いているときは止めない
- Claude の作業が終わり、バックグラウンドでシェルや Monitor だけが動いているときは、セッションは待機中になる。指示はそのまま送れて、預けられない（Claude Code 自身は、このときも `claude agents` で作業中と報告する）。サブエージェントやワークフローが動いているあいだは、Claude はその結果を待って続けるので、作業中のままで、停止ボタンはそれらを止める（シェルは止めない）

### モデル・Effort・Ultracode

- 入力欄で、モデル（既定・Opus 5.5 など、Claude Code の選択画面と同じ名前）、Effort（Low〜Max）、Ultracode（Effort のメニューの中のスイッチ）を選んで送ると、送る前にそのセッションだけ切り替える。全体の既定は変えない。新しく起動するセッションのモデルと Effort は、設定の「既定のモデル」と「既定の Effort」で決める。会話の途中でモデルを変えると、次の返答では履歴を新しいモデルで読み直すので、時間とトークンが多くかかる
- モデルの名前は、gasho-daemon が Claude Code の `/model` の選択画面から読んで覚える。覚えていないか24時間たったときは、待機中のいちばん新しい Gasho のセッションで選択画面を開いて閉じるので、その会話に `/model` の記録が残る
- 入力欄に `/model` や `/effort high` のように書いて送ることはできない。すべての新しいセッションの既定も変えてしまうため。`/effort ultracode on` と `off` は送れる

### スキルとコマンドの候補

入力欄に `/` を打つと、そのセッションの Claude Code が読むスキルとカスタムコマンドを、名前と説明の先頭の 1 行ずつで、入力欄の上に並べる。

- 続けて打った文字で絞り込む（`/impl` で `/impl-review` が残る。`/review` のように名前の途中の `-`・`:` の後ろからでも見つかる）。↑↓ で選んで Tab か Enter を押すと、入力欄に `/<名前> ` が入る（送りはしない）。スマホでは行を押す。Esc か、入力欄の外を押すと閉じる
- 並べるのは、`~/.claude` のスキル（`skills/`）とコマンド（`commands/`）、セッションのフォルダーからリポジトリの一番上までの `.claude/skills` と `.claude/commands`、有効なプラグインのもの（`/<プラグイン>:<名前>`）、claude.ai から同期されたスキル（`/anthropic-skills:<名前>`）
- Claude Code に組み込みのコマンド（`/model`・`/clear` など）、`user-invocable: false` のスキル、設定の `skillOverrides` で `off` にしたものは出さない
- 一覧は、`/` を打ったときに gasho-daemon がセッションのフォルダーをもとに読み、1分たつまでは読み直さない

### シェルのコマンド（!）

入力欄に「!」で始まる文を入れると、Claude Code の「!」（シェルモード）と同じく、working server のセッションのフォルダーで、シェルのコマンドとして実行する。入力欄には「! シェル」と出て、文字が等幅になり、送信ボタンは「実行」になる。

- 会話には、コマンドと出力を1つにまとめて出す（失敗したコマンドの出力は赤）。Claude Code はコマンドが終わってから会話に記録するので、それまでは「実行中…」と出す。止めるには停止ボタン（Esc）を押す
- ファイルは添付できない
- Claude Code 2.1.323 では、コマンドが終わると Claude がその出力に返答する
- コマンドは Claude Code の権限の確認を通らずに実行される

### 添付と下書き

- クリップのボタン、ドラッグ、貼り付けでファイルを添付できる（1回に5個、合わせて10MB まで）。ファイルは working server の `~/.local/share/gasho/attachments/` に保存され、Claude が読む。セッションが終わると消える
- 書きかけた文、添付したファイル、選んだモデル・Effort・Ultracode、↑ で呼び出せる送った文は、セッションごとに覚えておく。ほかのセッションやホームに移って戻っても残る。ページを開いているあいだだけ覚えるので、読み込み直すと消える

## パネル

ヘッダーのボタンで、セッションの右にパネルを開く（スマホでは画面全体）。スマホでは、パネルの題名と右上のボタンを画面上部のバーに出し、バーの左の ← でセッションに戻る。ボタンがバーに入りきらないときは、ボタンの並びを横にスクロールする。

### ブランチグラフ

ヘッダーのブランチ名を押すと開く。セッションのリポジトリのブランチと、全ブランチの新しいほうから300件のコミットを、枝分かれとマージの線で表示する。

- ブランチの一覧には、ローカルのブランチ（push していないコミットの数など）と、リモートにだけあるブランチ（雲のアイコン）を並べる。見出しを押すと、一覧を折りたためる
- コミットの件名は省略せずに出す。長い件名は、その行を横にスクロールして読む
- ブランチ名の右のアイコンは、GitHub のそのブランチのページを開く

### Issues と Pull requests

GitHub プラグインを入れると、ブランチ名と「ファイル」のあいだに「Issues」「Pull requests」が出る。押すと、リポジトリの開いている Issue と Pull request の一覧を開く。項目を押すと、本文とコメント（Pull request ではレビュー、チェック、変更したファイルも）を Gasho の中で読める。GitHub のページは、パネルの「GitHub」から開く。working server の GitHub CLI（gh）で読むので、working server で `gh auth login` を済ませておく。Gasho は GitHub のトークンを扱わない。

### ファイル

ヘッダーの「ファイル」を押すと、そのセッションのフォルダーのファイルを開く。

- フォルダーを押すと中に入り、上の場所の表示から前のフォルダーに戻れる。フォルダーを先にして名前の順に並べ、ファイルには大きさと最終更新を添える。`.git` は出さない
- ファイルを押すと中身を開く。テキストは行番号を付けて出し、Markdown と SVG は「表示」と「テキスト」を切り替えられる。画像（PNG、JPEG、GIF、WebP など）は画像として出す。開けるのは、テキストは 1MB、画像は 5MB まで。バイナリのファイルと、UTF-8 でないテキストは表示しない
- 「折り返す」で長い行を折り返す。ブラウザーごとに覚え、スマホでは折り返す状態から始まる
- 「編集」を押すと書き換えられ、「保存」（Ctrl+S・⌘S）で working server のファイルに書き込む。改行コード（CRLF）と BOM は、元のまま保つ。読み取り専用のファイルは編集できない
- 保存しようとしたファイルが、開いたあとで変わっていたとき（Claude が書き換えたときなど）は、上書きせずに知らせる。「上書きして保存」を押したときだけ上書きする。「編集を捨てて読み込み直す」で、いまの中身を開き直す
- 編集中の内容は、ほかのファイルやセッションに移っても残り、フォルダーの一覧には「未保存」と出る。ページを開いているあいだだけ覚えるので、読み込み直すと消える（その前にブラウザーが確かめる）
- フォルダーの「新しいファイル」で、そのフォルダーに空のファイルを作り、編集の画面で開く。同じ名前のファイルやフォルダーがあれば作らない
- 読み書きできるのは、セッションのフォルダーの中だけ。フォルダーの外を指すシンボリックリンクは、一覧に「フォルダーの外」と出すが、開かない
- 保存と作成は、ファイルのパスと大きさを操作のログに残し、ホームの「最近の操作」に出す。ファイルの中身は Gasho サーバーに残さない

## ホーム

- Gasho が起動したセッションが使ったトークンを、過去24時間の推移と内訳（入力、出力、キャッシュへの書き込み、キャッシュからの読み込み）で見られる。gasho-daemon が、セッションとそのサブエージェントの会話の記録（`~/.claude/projects/` の下）から、返答ごとに1回ずつ数える。キャッシュからの読み込みは、それまでの会話を毎回読み直した分で、たいてい全体の大部分を占める
- 「メモリ」のタイルで、working server ごとのメモリの使用率と使用量／総量を見られる。gasho-daemon が 15 秒ごとに読み、ページキャッシュは使用中に数えない。80% 以上で「注意」、90% 以上で「警告」と出る。オフラインのサーバーは「オフライン」、メモリの値を送らない古い gasho-daemon のサーバーは「未対応」と出る
- タイルは、上の辺の真ん中にあるつまみをドラッグして並べ替えられる。つまみは、PC ではタイルにポインターを乗せると出て、スマホではいつも出ている。ドラッグ中は、ほかのタイルが場所を空け、画面の上端・下端に近づけるとスクロールする。Esc を押すと元の並びに戻る。つまみにフォーカスして、矢印キーでも動かせる。並びはブラウザーごとに覚える。見出しの横に出る「並びを元に戻す」で、最初の並びに戻る

## 端末とバージョン

画面の「端末」で、登録した端末の一覧、名前の変更、登録の取り消し、登録コードの発行ができる。取り消した端末の接続はすぐに切れる。Gasho サーバーのコマンドでも操作できる。

```bash
npx @4rtofl/gasho-hub devices          # 一覧（clone では npm run hub:devices）
npx @4rtofl/gasho-hub revoke <端末の ID>  # 取り消し（30秒以内に接続が切れる。clone では node apps/hub/src/cli.ts revoke）
```

いま動いているバージョンは、サイドバーの「設定」の「バージョン」の欄にまとめて出る。Gasho サーバー（clone から動かしているときは commit の短い SHA も）・画面のビルド・プラグインの API と、working server ごとの gasho-daemon とそのプラグインの API のバージョンを並べる。新しいバージョンが公開されているものには「〜に更新できます」が出て、押すと「端末」の画面の更新の欄へ移る。「バージョンをコピー」で、欄のバージョンをまとめてテキストでコピーできる。不具合を伝えるときに貼る。

## プラグイン

Gasho の画面と gasho-daemon には、プラグインで機能を足せる。プラグインは [GashoPlugins](https://github.com/4rtofl/GashoPlugins) に置く。GitHub の Issues と Pull requests のパネル、ホームの GitHub のタイルも、GitHub プラグイン（`github`）である。作り方は [plugins.md](plugins.md) を見る。

- サイドバーの「プラグイン」の画面で、GashoPlugins にあるものから選んで追加する。ジャンル（連携、開発ツールなど）ごとに分けて出す
- 有効・無効をスイッチで切り替え、カタログに新しい版があれば更新し、外す（ゴミ箱のボタン）ことができる。どれも、Gasho サーバーと gasho-daemon を起動し直さずに、開いている画面と gasho-daemon にすぐ反映する
- daemon の部分（working server で動く部分）は、有効なプラグインなら、すべての working server で動く。プラグインに対応していない古い gasho-daemon の working server では、プラグインの画面に「gasho-daemon が古い」と出る
- GashoPlugins の GitHub Actions が、版を上げたプラグインをビルドしてリリースに置き、プラグインの一覧（カタログ）を作る。Gasho サーバーは、そのカタログとプラグインを、Gasho サーバーのマシンの GitHub CLI（gh）で取ってくる。Gasho サーバーのマシンで `gh auth login` を済ませておく
